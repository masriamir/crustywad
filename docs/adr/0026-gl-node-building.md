# ADR-0026: GL node building and the XGLN/XGL2/XGL3 extended-node writer

- **Status:** Accepted
- **Date:** 2026-07-25
- **Deciders:** @masriamir
- **Tracking issue:** https://github.com/masriamir/crustywad/issues/345

## Context and problem statement

crustywad can build classic BSP nodes (ADR-0024: `build_nodes` →
`BuiltNodes`, the `SEGS`/`SSECTORS`/`NODES` lumps) and can serialize that
same `BuiltNodes` as the ZDoom **non-GL** extended stream (`XNOD`/`ZNOD`,
the #323 amendment to ADR-0025). It cannot emit any of the **GL** extended
formats — `XGLN`/`XGL2`/`XGL3` and their zlib `Z*` twins — which is what the
ZDoom family actually requires for UDMF maps and what the standard UDMF
toolchain emits. This blocks `cwad build --nodes` for UDMF (#354) and full
UDMF format parity (#257).

The gap is structural, not a missing serializer. `BuiltNodes` carries
classic node data only:

- **No minisegs.** Every `BuiltNodes` seg has `linedef: Some(..)`; both
  serializers reject `None` with `NodeBuildError::MinisegUnsupported`. GL
  subsectors are closed convex polygons whose partition-line edges are segs
  with no backing linedef.
- **No partner segs.** `MapSeg` has no partner field. GL segs pair each
  two-sided edge with its mirror in the adjacent subsector.
- **No fractional precision.** The classic kernel rounds every split
  intersection to whole map units as the split vertex is created (it is
  interned as whole-unit integers; ADR-0024 §3 narrow-first-build-second)
  and stores node partitions as whole units.
  `XGL3` exists precisely to carry 16.16 fixed-point partition lines.

Nor can GL data be recovered from a *read* map: the extended reader
(`map/extended.rs`, #326) validates and then **discards** each GL seg's
partner, and truncates `XGL3`'s 16.16 partitions to whole units
(arithmetic shift by 16) when populating `MapNode`. A `Map` read from
`XGL3` therefore cannot round-trip; GL data must be **generated by a
GL-aware build pass**, exactly as anticipated by ADR-0025's revisit
condition (a) and ADR-0024's revisit condition (a).

### What the codec requires of a GL writer (verified against `map/extended.rs`)

The writer must be the byte-exact inverse of the crate's own reader
(`decode_body`), the same GOLDEN discipline that anchored the #323 `XNOD`
writer. All eight tags share one framing; little-endian throughout:

- **Vertex header:** `u32 origVerts`, `u32 newVerts`, then `newVerts` ×
  (`i32 x`, `i32 y`) in 16.16 fixed-point. Builder-added vertices are
  fractional-capable in **every** variant, `XGL3` or not.
- **Subsector block:** `u32 numSubs`, then `numSubs` × `u32 segCount`;
  subsectors are consecutive seg runs, and the seg block's `u32 numSegs`
  must equal the sum of the counts.
- **Seg record** (the GL/non-GL split):
  - `XNOD` (11 bytes): `u32 v1`, `u32 v2` (explicit), `u16 linedef` (no
    sentinel — every index up to `0xFFFF` is a real linedef), `u8 side`.
  - `XGLN` (11 bytes): `u32 v1`, `u32 partner` (`0xFFFF_FFFF` = no
    partner), `u16 linedef` (`0xFFFF` = miniseg), `u8 side`. **No `v2` on
    disk**: the reader reconstructs each seg's end as the next seg's start
    within its subsector run, wrapping the last seg back to the first.
  - `XGL2`/`XGL3` (13 bytes): as `XGLN` but `u32 linedef`
    (`0xFFFF_FFFF` = miniseg).
- **Node record:** partition `x, y, dx, dy` as `i16` whole units
  (`XGLN`/`XGL2`, 32-byte record) or `i32` 16.16 fixed-point (`XGL3`,
  40-byte record); then 4 × `i16` right bbox `[top, bottom, left, right]`,
  4 × `i16` left bbox (whole units in **all** variants, `XGL3` included),
  `u32` right child, `u32` left child, bit 31 set = subsector leaf. Root is
  the last node.
- **Compression:** each `Z*` lump is its 4-byte tag followed by a zlib
  stream inflating to the `X*` twin's tag-less body (ADR-0025 §5).
- **Carrier lump (binary maps):** the non-GL `XNOD`/`ZNOD` stream lives in
  `NODES`; the GL `XGL*`/`ZGL*` family lives in `SSECTORS` (zdbsp's
  convention, mirrored by the reader's probe order in
  `Map::assemble_with_options`). UDMF carries either family in `ZNODES`
  (#354's concern, not this ADR's).

Because seg `angle` and `offset` are not stored in any extended format —
the reader derives them — the GL builder does not need to produce them.

## Decision drivers

- **UDMF is the consumer.** #354 (`build --nodes` for UDMF) and #257
  (format parity) need GL emission; `XGL3`/`ZGL3` is the modern common
  case.
- **Zero regression risk to the shipped classic builder.** `build_nodes`
  is released (0.9.0), retail-swept, and frozen by ADR-0024's explicit
  narrow-first-build-second decision.
- **Exact-arithmetic philosophy.** ADR-0024 §3's integer-exact geometry
  (no float comparisons deciding topology) must survive the move to
  fractional coordinates.
- **One data path / type reuse (ADR-0015).** The #324 amendment to
  ADR-0025 already established separate GL arenas and types (`GlSeg` with
  `partner` and `GlVertexRef` endpoints, `GlSubsector`, `GlNodeChild`) —
  the natural output vocabulary for a GL builder.
- **Reviewable staging.** The effort is larger than #323 (a new BSP kernel
  plus six formats plus CLI); it must land as an epic of bounded PRs.
- **ADR-0016 hardening** applies to the new build surface.

## Considered options

1. **Separate GL builder module** — a new `build_gl_nodes` kernel,
   16.16-native, in its own module; pure math helpers extracted into a
   submodule shared with the classic kernel; classic kernel otherwise
   untouched.
2. **Parameterized single kernel** — generalize the existing `Bsp` kernel
   over a coordinate scale (1 = classic, 65536 = GL) with GL-only branches
   for minisegs, partners, and the GL vertex namespace.
3. **GL-primary rebuild** — what zdbsp does: one GL-native kernel always;
   classic output derived by stripping minisegs and rounding at the end.

## Decision outcome

Chosen option: **1 — separate GL builder module**, because it is the only
option that adds GL capability with zero behavioral risk to the shipped
classic path while letting the GL kernel be fixed-point-native rather than
contorted around a scale parameter. It is also consistent with how the
crate has repeatedly modeled GL: a GL BSP is *a second, independent BSP*
(the #324 separate-arena decision), not a flag on the classic one.

The cost is real and accepted: the partition-loop skeleton exists twice,
so a future heuristic improvement must be applied in both kernels. That
duplication is of *stable* code (the classic kernel is complete and
frozen-ish); option 2's cost would instead be permanent complexity in, and
re-verification of, shipped code. Option 3 would change classic output
(end-rounding is not creation-rounding), overturning ADR-0024 §3 and
destabilizing a swept builder mid-0.x; it is recorded as a possible future
consolidation, not taken now.

### Consequences

- Good, because UDMF node emission (#354) and format parity (#257) become
  unblocked by a self-contained new surface.
- Good, because the classic builder's behavior, tests, and retail-sweep
  results are untouched by construction (only pure-helper extraction, with
  unchanged outputs, touches `nodes.rs`).
- Good, because the writer reuses #323's serialization plumbing and GOLDEN
  test discipline, and the read side already exercises every byte layout.
- Bad, because two BSP kernels now exist; heuristic or bug fixes to
  selection/classification must be considered for both (mitigated by the
  shared `geom` helpers carrying the subtlest math).
- Neutral, because `BuiltNodes` and `BuiltGlNodes` remain independent
  outputs; a caller wanting both classic and GL lumps runs both builds.

## Design

### 1. Module layout and public API

- **`map/build/geom.rs` (new, crate-internal):** the pure geometry both
  kernels share — exact cross product, on-line epsilon test, partition
  scoring, BAM angle, bbox union, 16.16 conversion, rounding helpers.
  Extracted from `nodes.rs` with **zero behavior change**, proven by the
  existing unit/golden/sweep tests.
- **`map/build/gl_nodes.rs` (new):** the GL kernel, `BuiltGlNodes`, and
  its serializer. Gated behind the existing `nodebuild` feature.

New public API, sketched below with attributes and doc comments elided
for brevity. In the implementation, every struct-shaped item is
`#[non_exhaustive]` and every public item carries full doc comments per
house rules (`missing_docs = "deny"`); the `//` annotations here are
sketch notes, not the shipped documentation:

```rust
/// Builds GL BSP nodes (minisegs, partner segs, fractional splits) from an
/// assembled map.
pub fn build_gl_nodes(
    map: &Map,
    opts: &NodeBuildOptions,
) -> Result<(BuiltGlNodes, Vec<NodeBuildWarning>), NodeBuildError>;

/// The GL node arenas produced by `build_gl_nodes`.
pub struct BuiltGlNodes {
    /// Builder-created vertices (splits and miniseg endpoints), quantized
    /// to 16.16 at creation; `GlVertexRef::Gl` indices point here.
    pub gl_vertices: Vec<GlVertex>,
    /// GL segs, in subsector-run order; reuses the read model's `GlSeg`
    /// (`GlVertexRef` endpoints, `linedef: Option<LinedefIdx>` with `None`
    /// = miniseg, `side`, `partner: Option<GlSegIdx>`).
    pub segs: Vec<GlSeg>,
    /// Contiguous seg runs; each run is a closed convex loop in traversal
    /// order (the implicit-`v2` contract).
    pub subsectors: Vec<GlSubsector>,
    /// GL nodes; root is the last node.
    pub nodes: Vec<BuiltGlNode>,
}

/// A built GL node. Unlike the read model's `GlNode` (whole map units),
/// partition fields are i32 16.16 fixed-point — the precision `XGL3`
/// serializes and the other variants narrow from.
pub struct BuiltGlNode {
    pub x: i32,                 // 16.16 fixed-point
    pub y: i32,                 // 16.16 fixed-point
    pub dx: i32,                // 16.16 fixed-point
    pub dy: i32,                // 16.16 fixed-point
    pub right_bbox: [i32; 4],   // whole map units, [top, bottom, left, right]
    pub left_bbox: [i32; 4],
    pub right: GlNodeChild,
    pub left: GlNodeChild,
}

impl BuiltGlNodes {
    /// Fallible constructor for hand-built values (`#[non_exhaustive]`
    /// blocks struct literals outside the crate); runs `validate`.
    pub fn new(
        gl_vertices: Vec<GlVertex>,
        segs: Vec<GlSeg>,
        subsectors: Vec<GlSubsector>,
        nodes: Vec<BuiltGlNode>,
        orig_vertex_count: usize,
    ) -> Result<Self, NodeBuildError>;

    /// Structural validation (the #349 pattern, plus GL invariants):
    /// subsector runs exactly partition `segs`; vertex refs in range
    /// (`Normal` against `orig_vertex_count`, `Gl` against
    /// `gl_vertices`); node children in range; partner links symmetric
    /// (`partner[partner[i]] == i`, never self); each subsector run a
    /// closed loop (`seg.end == next.start`, wrapping).
    pub fn validate(&self, orig_vertex_count: usize) -> Result<(), NodeBuildError>;

    /// Serializes as one GL extended-node lump. `format` must be a GL
    /// variant; `NodeFormat::Gl`/`Zgl` resolve to a concrete dialect
    /// first (§3).
    pub fn to_extended_lump_bytes(
        &self,
        orig_vertex_count: usize,
        format: NodeFormat,
    ) -> Result<Vec<u8>, NodeBuildError>;
}
```

`BuiltGlNodes` follows ADR-0024's contract shape: it does not mutate
`Map`; callers observe warnings on success via the `(value, warnings)`
tuple, matching `build_nodes`.

### 2. The GL kernel

**Coordinates.** All geometry runs in 16.16 fixed-point `i32` (map
vertices widened by `<< 16` at kernel entry, after the same i16 narrowing
gate as the classic kernel). Every split vertex is created in this space,
rounded to the nearest 1/65536 unit — topology decisions stay exact
integer arithmetic (cross products through `i128`, which the classic
kernel already uses for its epsilon test), preserving ADR-0024 §3's
philosophy at finer granularity. New vertices are deduplicated by exact
16.16 coordinates; vertices coincident with an original map vertex resolve
to `GlVertexRef::Normal`, others intern into `gl_vertices` as
`GlVertexRef::Gl`.

**Initial segs, partnered from birth.** One seg per present sidedef, as
in the classic kernel; the two segs of a two-sided linedef are linked as
partners at creation. The kernel maintains two invariants from then on:
partnership is symmetric, and partners always cover the same edge span
(splitting one splits the other at the identical interned vertex, with the
four fragments re-linked pairwise).

**Selection and splitting.** The candidate-scoring heuristic
(`split_cost`, balance, axis-aligned preference, the 512-candidate
sampling budget), classification, and canonical-geometry intersection all
carry over structurally via the shared `geom` helpers. `NodeBuildOptions`
is reused unchanged (`format` selects the GL target, §3).

**Miniseg synthesis — inside the recursion.** After distributing a split
set front/back, the partition line itself is covered: collect every point
where the working set touches the partition line (the split's interned
vertices and colinear-seg endpoints), sort them along the line, and for
each interval interior to the level geometry (determined from the sector
occupancy of the adjacent colinear and split segs), emit a **mirrored
miniseg pair** — one facing front, one back, partners of each other,
`linedef: None`. The pair enters the front/back working sets respectively
and flows down the recursion like any seg (later splits may split it,
maintaining partner pairing). The interval-occupancy rule is the
historically bug-prone heart of GL node building and receives the densest
unit and property coverage (§6).

**Leaf finalization.** A subsector's segs are ordered into their closed
convex loop (each seg's end vertex is the next seg's start vertex,
wrapping) — the property that makes on-disk implicit-`v2` decode correct.
Gaps in that loop — where a seg's end vertex is not the next seg's start —
are closed by partner-less **connecting minisegs** in **both** modes as
normal operation, matching the source-verified ZDBSP `CloseSubsector`
behavior. **Degenerate leaves** (fewer than 3 distinct vertices) are closed
by this same connecting-miniseg path and emitted normally in both modes — a
1-seg leaf `A→B` becomes a closed 2-vertex loop (seg `A→B` + connecting
miniseg `B→A`). There is no error and no warning: the retail sweep measured
degenerate leaves on 547 of 551 classic maps, and ZDBSP emits them routinely
(`OutputDegenerateSubsector`), so they are normal GL output, not an
exception. The mixed-sector-fan handling itself carries over with identical
semantics.

**Discipline.** Explicit work stack (no call recursion); live-seg growth
(splits *and* minisegs) capped by `MAX_EXTENDED_INDEX`, bounding work and
allocation; bboxes computed per leaf and unioned bottom-up, rounded
**outward** to whole units at flatten (top/right ceil, bottom/left floor)
so every bbox contains its subtree's fractional geometry.

### 3. `NodeFormat`, auto-selection, and the one-shot

`NodeFormat` (additive; the enum is `#[non_exhaustive]`, and
`is_extended`'s deliberately exhaustive match forces each new variant to be
classified before the crate compiles):

| Variant | Emits | Gate |
|---|---|---|
| `Xgln` / `Xgl2` / `Xgl3` | that exact GL dialect | — |
| `Gl` | minimal sufficient GL dialect (below) | — |
| `Zgln` / `Zgl2` / `Zgl3` / `Zgl` | zlib twin of the above | `extended-nodes-zlib` |

Auto-resolution for `Gl`/`Zgl`, applied to a `BuiltGlNodes` before
serialization, escalates only when forced by the codec:

- start from `XGLN`;
- escalate to `XGL2` when any real linedef index would collide with the
  16-bit miniseg sentinel (i.e. does not fit below `0xFFFF`);
- escalate to `XGL3` when any node partition value is fractional (nonzero
  low 16 bits) or its whole part does not fit `i16`.

Builder-added vertices never force escalation — the vertex header is 16.16
in every variant. Serializing an explicit `Xgln`/`Xgl2` that cannot
represent the data (sentinel collision, fractional or out-of-range
partition) is a hard error (§4) — the situation `Gl` exists to avoid.

The serializer reuses #323's plumbing (presized exact-capacity buffer,
`encode_u32`/`encode_index_u32`, bit-31 child encoding, the
`Z*` tag + zlib-level-6 wrapper) — but writes GL vertices with the
fraction-preserving `fixed_16_16_exact` (added in #364), not the whole-unit
`fixed_16_16` #323 uses, since GL split vertices carry sub-unit coordinates. It
flattens `GlVertexRef` into the
on-disk unified index space: `Normal(i)` → `i`, `Gl(j)` →
`orig_vertex_count + j`. Partner `None` and miniseg `None` emit their
sentinels. No `v2` is written; the subsector loop order carries it.

**One-shot.** `add_doom_map_with_nodes` with a GL format places the
stream in **`SSECTORS`** with `SEGS` and `NODES` empty — the inverse of
the reader's probe and zdbsp's convention — keeping `VERTEXES` untouched
(builder vertices live in the stream header). Non-GL and classic behavior
is unchanged. UDMF's `ZNODES` carrier is #354.

**CLI.** `cwad convert --node-format` and `cwad build --nodes` gain
`xgln|xgl2|xgl3|gl` (and `z*` forms where the binary is built with
`extended-nodes-zlib`), binary Doom-format maps only; UDMF wiring is #354.

### 4. Errors, warnings, strictness

`NodeBuildError` additions (both modes honored throughout):

- a partition-precision variant for explicit `Xgln`/`Xgl2` serialization
  of fractional or out-of-`i16` partitions (hard error, not
  lenient-recoverable — the caller asked for an unrepresentable format);
- a misuse rejection for passing a non-GL `format` (`Classic`/`Xnod`/
  `Znod`) to `BuiltGlNodes::to_extended_lump_bytes` — an error in both
  modes, never a panic;
- `InvalidStructure` grows GL variants (partner asymmetry, open subsector
  loop, GL vertex reference out of range) surfaced through
  `BuiltGlNodes::validate`;
- existing variants (`EmptyGeometry`, `TooManyElements`,
  `MixedSectorSubsector`, `DegeneratePartition`, `CompressionUnavailable`)
  apply as-is.

`NodeBuildWarning` grows the lenient twins (unclosed-loop best-effort
emission; mixed-sector fan as today). `is_lenient_recoverable` is updated
accordingly.

### 5. Hardening (ADR-0016)

Stated per implementing PR: (1) allocation is `O(input)` under the
live-seg cap — minisegs are bounded by splits, vertices by segs; (2) no
unbounded recursion — explicit work stack; (3) a `fuzz_build_gl_nodes`
target: arbitrary small assembled maps → `build_gl_nodes` → `validate` →
serialize → decode through the crate's own `XGL*` reader, with the
no-panic oracle and output-size assertions, seed corpus committed, wired
into `fuzz.yml`; (4) both strictness modes reject or recover without
panicking.

### 6. Testing and validation

- **Unit:** handcrafted tiny maps with hand-derived expectations — a
  single square room (one subsector, known loop order), a split forcing a
  miniseg pair, a fractional split forcing `XGL3`.
- **Golden bytes:** writer output equals the reader-side integration
  fixtures (`xgl3_stream` family in `tests/extended_nodes.rs`) — the #323
  GOLDEN discipline.
- **Round-trip:** write → decode via the #326 reader → compare everything
  that survives read, with the documented losses (partners dropped,
  `XGL3` partitions truncated) explicitly excluded; implicit-`v2`
  reconstruction must reproduce the kernel's seg endpoints exactly.
- **Invariants:** convexity of every subsector, closed loops, partner
  symmetry, miniseg pairing — as tests, in `validate`, and in the fuzz
  oracle; proptest over small random maps.
- **Retail sweep:** a `sweep-tests` stage building GL nodes for every map
  group in the local collection, validating and re-decoding each.
- **Acceptance (manual, epic close):** a WAD built with our `XGL3` nodes
  loads and renders in GZDoom.

### 7. Staging

#345 becomes an **epic** with native sub-issues, each its own PR
(milestone `GL nodes`):

| Sub-issue | Content |
|---|---|
| A — `geom` extraction | shared pure helpers out of `nodes.rs`; zero behavior change |
| B — GL kernel core | `build_gl_nodes` → `BuiltGlNodes` + `validate` + unit/invariant/proptest + fuzz target |
| C — `XGL3`/`ZGL3` writer | serializer + golden + round-trip + `NodeFormat::Xgl3`/`Zgl3` + one-shot `SSECTORS` carrier |
| D — `XGLN`/`XGL2` + auto | remaining dialects, `Z*` twins, `Gl`/`Zgl` resolution |
| E — CLI + docs | `convert`/`build` flags, guide/README/features sync, sweep hook, GZDoom acceptance |

## Pros and cons of the options

### 1. Separate GL builder module (chosen)

- Good, because the shipped classic builder is untouched — no
  re-verification burden, no behavioral risk.
- Good, because the GL kernel is 16.16-native throughout: no scale
  parameter threading, no dual-personality branches.
- Good, because it matches the crate's established GL modeling (#324:
  separate arenas and types for a genuinely separate BSP).
- Bad, because the partition-loop skeleton is duplicated; heuristic
  changes must be applied twice (mitigated: the subtlest math lives in
  shared `geom` helpers).

### 2. Parameterized single kernel

- Good, because selection/classification heuristics exist once.
- Bad, because GL concerns (miniseg synthesis, partner tracking, GL
  vertex namespace) thread through a shipped 2,800-line kernel — every
  classic invariant must be re-proven, and classic output must be shown
  byte-identical.
- Bad, because the kernel becomes permanently harder to read: two
  coordinate scales, mode branches at each stage, `i128` widening imposed
  on the classic path.

### 3. GL-primary rebuild (zdbsp-style)

- Good, because one kernel serves both outputs forever (zdbsp-proven
  architecture; classic = GL minus minisegs, rounded).
- Bad, because end-rounding is not creation-rounding: classic output
  changes, overturning ADR-0024 §3 and invalidating the swept baseline
  mid-0.x.
- Bad, because it couples a large new capability to a risky rewrite of a
  finished one.
